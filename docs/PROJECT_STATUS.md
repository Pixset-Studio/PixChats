# PixChats — состояние проекта

Документ описывает, что уже реализовано, как устроен проект, и что осталось сделать.
Обновлено по состоянию на текущий момент разработки Фазы 1.

---

## 1. Обзор

PixChats — мессенджер уровня Telegram с сквозным шифрованием (задел под него), голосовыми/видеозвонками (запланировано), веб/десктоп/мобильными клиентами на одной кодовой базе.

**Статус: Фаза 1 (Фундамент) реализована в очень широком объёме** — фактически проект давно перерос рамки исходного плана "Фаза 1" и включает в себя много функций, изначально запланированных на более поздние фазы (модерация, приватность, звонки — кроме самих звонков, уведомления, ПК-раскладка).

## 2. Технологический стек

| Слой | Технология |
|---|---|
| Frontend | React 18 + TypeScript, Next.js (static export) |
| Стилизация | Чистый CSS (design tokens в `globals.css`), без Tailwind |
| Backend | Supabase (Postgres + Auth + Realtime + Storage + Edge Functions) |
| Хостинг | GitHub Pages (статическая выгрузка) |
| Звонки (запланировано) | WebRTC + Cloudflare Realtime TURN |
| Email | Custom SMTP через Gmail/Google Workspace |
| OAuth | Google (нативно), VK и Яндекс (Custom OIDC Providers) |

## 5. Что реализовано (функционально)

### Аутентификация и аккаунт
- Регистрация email/пароль с подтверждением **кодом** с почты (не ссылкой)
- Вход по паролю **или** по одноразовому коду с почты
- OAuth: Google (нативно), VK и Яндекс (Custom OIDC)
- Привязка дополнительных способов входа к уже существующему аккаунту
- Гео-скрытие кнопки Google для посетителей из РФ
- Согласие на обработку персональных данных при регистрации (152-ФЗ) + страница `/privacy`
- Кастомные русские письма (подтверждение, код входа, сброс пароля)

### Профиль и роли
- `@username`, отображаемое имя, аватар, описание ("о себе"), дата регистрации
- Роли: `user`, `partner`, `moderator`, `admin`, `developer` — с уникальными иконками-бейджами
- Отдельный бейдж "Сотрудник Pixset Studio" (не связан с ролью)
- Синяя галочка верификации — заменяется на ❄️, если аккаунт заморожен
- last_seen обновляется при активности, с настраиваемой видимостью (всем/друзьям/никому)

### Чаты
- Личные чаты, группы, каналы (публичные/приватные)
- Жёсткая защита от дублей личных чатов на уровне БД (`direct_pair_key`, уникальный индекс)
- Создание/редактирование (аватар, название, описание, юзернейм) — только владелец/админ
- Полное удаление группы/канала владельцем (каскадно сносит сообщения/участников)
- Подписка/отписка (каналы), вступление/выход (группы) — прямо в окне чата
- Список участников/подписчиков с возможностью добавить (из друзей) или удалить
- Приватность "кто может добавить меня в группу/канал" (все/друзья/никто)
- Публичная ссылка на чат под описанием

### Сообщения
- Текст (многострочный, Shift+Enter — новая строка), эмодзи-панель
- Фото/видео/аудио/файлы любого типа — с подписью (сверху или снизу)
- Голосовые сообщения (запись через микрофон в браузере)
- Ответ, пересылка (с исключением чатов, где нельзя писать), копирование
- Редактирование (с пометкой "изменено"), удаление "у всех" (soft-delete)
- Закрепление — в группах/каналах только владелец, в личных чатах — оба участника; открепление
- Прямые ссылки на сообщение с подсветкой при переходе (deep link)
- Разделители дней, время у каждого сообщения (слева/справа по стороне)
- Инлайн-превью фото/видео, аудиоплеер — без "коробки"-фона
- Аватар + имя отправителя над сообщением в группах/каналах
- Живая доставка сообщений через Supabase Realtime (без перезагрузки страницы)

### Друзья и приватность
- Заявки в друзья, принятие/отклонение, список друзей
- Блокировка пользователей (реально блокирует отправку сообщений на уровне БД)
- Настройки приватности: кто может написать первым, кто видит last seen, кто может добавить в группу — везде 3 варианта (все/друзья/никто)

### Непрочитанные и уведомления
- Счётчик непрочитанных в списке чатов (кружок), серый — если чат замьючен
- Живое обновление (без перезагрузки), синхронизация между открытым чатом и списком на ПК
- Мьют чата/человека на 1 час / 8 часов / навсегда, с обратным включением
- Браузерные push-уведомления о новых сообщениях (с запросом разрешения), учитывают мьют и открытый чат

### Админ-панель (`/admin`)
- Статистика: пользователи, DAU/MAU, чаты по типам, сообщения/звонки за сегодня
- Статус систем (ручная и автоматическая самопроверка при заходе)
- Логи ошибок
- Поиск пользователей, назначение ролей (только `developer`)
- Выдача/снятие галочки верификации и бейджа "Сотрудник Pixset Studio"
- Бан (на срок или навсегда), разбан, заморозка/разморозка, полное удаление аккаунта
- Запрет/разрешение конкретных юзернеймов

### Заморозка и бан — пользовательский опыт
- Забаненный видит отдельный экран с таймером обратного отсчёта (для временного бана) и не может попасть никуда, кроме `/banned`; при снятии бана — автоматический возврат
- Замороженный видит баннер во всех чатах, не может отправлять и не получает новые сообщения в реальном времени; галочка верификации заменяется на ❄️

### Интерфейс
- Тёмная/светлая тема, кастомная типографика (Space Mono + Inter), фирменный акцентный цвет
- ПК-раскладка (от 900px): рейл иконок + список чатов + окно чата, на всю ширину экрана
- Плавные анимации появления, логотип PixChats как favicon
- Кастомная 404-страница

## 6. Известные упрощения / технический долг

Эти места — осознанные компромиссы ради скорости на Фазе 1, отмечены как задачи для следующих фаз:

- **Шифрование сообщений — заглушка.** Сейчас это просто `base64(текст)`, а не настоящее сквозное шифрование. Реальный Signal Protocol (X3DH + Double Ratchet через `libsignal-client`) — это Фаза 2. Все ключевые поля (`public_identity_key` и т.д.) уже заведены в БД под это.
- **Файлы хранятся в Supabase Storage**, что расходует бесплатный лимит (1 ГБ). Перенос на Cloudflare R2 (без затрат на хранилище) требует Edge Function с presigned URL — не сделано.
- **Звонки не реализованы** — предусмотрены архитектурно (Cloudflare TURN, экран "занято"), но самого WebRTC-кода ещё нет.
- **Инвайты в группы — прямое добавление**, а не двухшаговое приглашение с подтверждением от приглашённого.
- **Push-уведомления работают только при открытой вкладке.** Полноценный push (когда сайт закрыт) требует Service Worker + VAPID-ключи + серверную часть — отдельная задача.
- **Групповое шифрование (Sender Keys) и SFU для групповых звонков** — не начаты, в первоначальном плане это Фаза 6.

## 7. Список миграций (обязательно по порядку)

От `0001_init.sql` до `0027_chat_members_delete_policy.sql` — 27 миграций. Полный список с комментариями — в `README.md` в корне проекта. Наиболее значимые фиксы багов среди них:
- `0009` — фикс триггера, блокировавшего ручное назначение ролей через SQL Editor
- `0011` — Realtime не был включён для таблицы `messages` (сообщения не приходили без перезагрузки)
- `0019` + `0025` — устранение дублей личных чатов (недостающий бэкфилл ключа пары)
- `0021` — блокировка пользователей была только "для вида", не мешала реально писать
- `0024` — у admin/developer не было RLS-права редактировать чужие профили (роли/бан/заморозка не работали)
- `0027` — на `chat_members` вообще не было DELETE-политики (выход из чата мог не срабатывать)

## 8. Дорожная карта: что дальше

Исходный план был из 6 фаз. Текущий прогресс:

1. **Фундамент** — ✅ реализовано (и сильно перевыполнено — многое из фаз 4–6 уже частично сделано)
2. **E2E-шифрование текста** — ⏳ не начато (заглушка на месте, схема БД готова)
3. **Медиа с шифрованием** — ⏳ не начато (сейчас файлы не шифруются, просто загружаются как есть)
4. **Звонки** — ⏳ не начато (архитектура описана: WebRTC + сигналинг через Supabase Realtime + Cloudflare TURN)
5. **Desktop (.exe) и Mobile (.apk)** — ✅ реализовано: Electron (Windows) и Capacitor (Android), обе сборки автоматические через GitHub Actions (`build-desktop.yml`, `build-mobile.yml`), локальный Android Studio/Windows-машина не нужны. Android-сборка пока debug (не подписана для Google Play)
6. **Групповое шифрование и SFU для групповых звонков** — ⏳ не начато

### Рекомендуемый следующий шаг
Фаза 5 закрыта — люди уже могут поставить PixChats как обычное приложение на Windows и Android, а не только открывать сайт. Логичный следующий шаг — **Фаза 2 (реальное шифрование)**: важно сделать это раньше, чем в проекте накопится много настоящих переписок, которые прямо сейчас хранятся как обычный base64, а не шифротекст.

Отдельно, не блокируя Фазу 2: если понадобится публикация в Google Play, Android-сборку нужно будет доподписать релизным keystore (сейчас она debug-only) — это небольшая отдельная задача.
